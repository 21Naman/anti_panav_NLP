# Methodology — Liar's Chatroom

Team: solo (Kaggle `panavrg`). Code: private repo `Panavdoesstuff/liars-chatroom`.
Sections marked **TODO (event)** are filled in during the competition; everything else
describes the pipeline as built and tested before the event.

## 1. Task

Each example has verified evidence facts and a group chat between four speakers (A–D).
Exactly one speaker states something that contradicts the evidence. We predict that
speaker; the metric is accuracy.

## 2. Fair-play statement

- **No external prediction APIs.** No Claude, OpenAI or other hosted model produced any
  prediction, label or training example. All predictions come from open-weight models
  that we ran ourselves on Kaggle GPUs (2x Tesla T4) or a laptop CPU.
- **No manual labelling of test data.** Test chats were never read or labelled by hand;
  only schema, counts and length statistics of the test set were inspected.
- **Synthetic data** (section 4) is generated by our own rule-based program from random
  "worlds". It contains no test data and no text from the competition.
- **Pseudo-labelling:** built but switched off (`pseudo.enabled: false`). **TODO (event):**
  state whether the organizers allowed it and whether it was used.
- No code or predictions were shared with other teams.

## 4. Synthetic data (used for development; optional pretraining)

- A generator builds a random world (events, objects, places, people with attributes such
  as time, day, price, owner, location, weather), samples evidence facts, and writes a chat
  where three speakers state only true or unverifiable things and one speaker makes a
  false claim. Eight lie types: number, time, day, location, owner, negation, implicit
  (implied by context), and two-step (an item is named in one message and the false detail
  is given later with "it").
- Every chat is checked against its world by a structural verifier (`synth/verify.py`).
  A leak check (TF-IDF on the text alone, one-feature rules, liar-only templates) must stay
  at chance (25%) so models cannot win on surface patterns. Ambiguous "it" lines that
  could refer to a different item are detected and re-drawn (`synth/ambiguity.py`).
- Two style packs (neutral sentences, casual texting) and three difficulty levels.

## 5. Validation scheme

- Stratified 5-fold split of the training set (`liars folds`, seed 42).
- Cheap models: 5-fold, out-of-fold (OOF) predictions for every training row.
- Expensive LLM runs: **holdout mode** — train on folds 1–4, predict fold 0 (the holdout)
  and the test set. Early stopping and temperature calibration use a small inner split
  of the training folds, never the holdout fold.
- Ensemble weights are fitted on the holdout predictions, and their accuracy is reported
  with an inner 5-fold so the score is not fitted to itself.

## 6. Models

| Model | What it does | Code |
|---|---|---|
| LLM zero-shot | Open instruct LLM (`google/gemma-4-12B-it`, 4-bit) reads evidence + chat and the question "which speaker contradicts the evidence?"; we read the probabilities of the tokens A/B/C/D at the answer position (no text generation, no parsing). Speaker-permutation test-time augmentation (TTA), temperature calibration. | `models/llm_zeroshot.py`, `llm.py`, `prompt.py` |
| **LLM QLoRA (main)** | Same prompt; LoRA adapters (r 16) on the attention and MLP projections of the 4-bit model, trained with cross-entropy over the 4 letter logits only. fp16 + gradient scaler, paged 8-bit AdamW, cosine schedule, early stopping. | `models/llm_qlora.py` |
| DeBERTa multiple choice | DeBERTa-v3-large (NLI-pretrained) scores 4 versions of the chat, each with one speaker's lines marked; softmax across the 4. | `models/deberta_mc.py` |
| NLI zero-shot | Each chat line checked against the evidence with an NLI model; contradiction scores aggregated per speaker. | `models/nli_zeroshot.py` |
| Rules (features) | Hand-written checks (e.g. number or day/time mismatch with the evidence); used only as ensemble features. **TODO (event):** rules written for the competition's phrasing. | `features/rules.py` |

Exact model ids and Hub revisions: see "Models used" in `PROGRESS.md`; package versions in
`requirements-lock.txt`.

## 7. Ensemble

`liars ensemble` aligns the runs on their shared held-out rows and compares: plain mean,
non-negative weights minimising log-loss, and a stacked conditional-logit model (per-speaker
features: probability, log-probability, rank, rule scores). Weighted and stacked are scored
with an inner 5-fold. `auto` picks the best of weighted / mean / best single run (accuracy
gaps under 0.3 points count as ties and go to the lower log-loss); stacking is used only if
it wins by more than 0.3 points.

## 8. Results

Pre-event benchmark (our synthetic data; holdout 400 chats, test 1000 chats):

| Model | Holdout | Test |
|---|---|---|
| LLM zero-shot (gemma-4-12B) | 84.5% | 84.3% |
| DeBERTa-large MC, 5-fold | 92.8% (93.7% all folds) | 95.8% |
| QLoRA gemma-4-12B | 97.5% | 96.8% |
| Mean of QLoRA + DeBERTa | 98.0% | 97.3% |
